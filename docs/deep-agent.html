三晚把业务 Agent 做稳

这不是再读一本 Agent 百科。三晚只做一件事：用 LangChain Deep Agents 把一条业务黄金路径箍住——说明书写清、硬约束上锁、Skill 可复用、结果有人独立检查。

三晚计划

Deep Agents 是一套现成的 agent harness：规划、文件系统、子 Agent、记忆、Skill、人在回路，都已经焊在 create_deep_agent 上。业务 Agent 做不稳，通常不是模型不够聪明，而是缰绳没装好——指令含糊、约束靠自觉、反馈靠运气、能力散落在聊天记录里。

三晚的节奏刻意很窄。每晚只交付一个能跑的增量，第二天接着箍。做完后你手里应有：一份说明书、一条黄金路径、一组硬约束、一个 Skill、一次独立检查。

  • 今晚：写说明书，钉死黄金路径，用最小 create_deep_agent 跑通。
  • 明晚：给写文件、发信、删数据这类动作加 permissions 与 interrupt_on。
  • 后天：把流程收进 SKILL.md，再派一个只读检查员验收。

橙皮书讲的是缰绳工程学的一般方法；本页只把它落到 Deep Agents 的 API 上。不摘录橙皮书正文。

今晚：说明书 + 黄金路径

说明书不是产品文案，是给模型的合同。写清角色、边界、输入、输出、以及「绝对不要做什么」。黄金路径是合同里的第一条可执行条款：从真实输入到可验收输出，中间步骤越少越好。

说明书要钉死的五句话

  1. 你是谁，服务哪条业务，不服务什么。
  2. 成功长什么样：一份结构化结果，而不是一段随口解释。
  3. 工具清单：只能用列出的工具，缺数据就停，不编造。
  4. 工作区：只读写约定目录，草稿和最终件分开。
  5. 停手条件：不确定、缺权限、或偏离黄金路径时，写明原因并等待。

把这五句话放进 system_prompt，稳定偏好再放进 memory（AGENTS.md）。说明书要短，短到你能大声读完还不喘。 

from deepagents import create_deep_agent
from deepagents.backends.filesystem import FilesystemBackend

SYSTEM_PROMPT = """你是售后库存助手，只处理「能否发货」这一条路径。
成功标准：写出一份含 sku、库存结论、建议话术 的草稿，放在 /workspace/outbox/。
不要 invent 库存；查不到就停。不要直接对客发送。
偏离黄金路径时，说明缺什么，然后等待。
"""

def lookup_stock(sku: str) -> str:
    """按 SKU 查询库存。查不到就返回 NOT_FOUND。"""
    return "sku=A-12 qty=8 warehouse=CN-EAST"

agent = create_deep_agent(
    model="anthropic:claude-sonnet-4-6",
    system_prompt=SYSTEM_PROMPT,
    tools=[lookup_stock],
    memory=["./AGENTS.md"],
    backend=FilesystemBackend(root_dir="./ops-agent"),
)

result = agent.invoke({
    "messages": [{"role": "user", "content": "客户问 A-12 今晚能否发 2 件"}]
})

黄金路径怎么验收

准备三组输入：一组正常单、一组库存不足、一组 SKU 不存在。今晚只要求正常单稳定产出草稿。失败案例先记下来，明晚用约束接住，不要今晚就加子 Agent。

明晚：硬约束

提示词是软约束。业务 Agent 要稳，必须把「不能写的路径」和「不能擅自执行的工具」写成代码。Deep Agents 给了两把锁：permissions 管内置文件系统工具；interrupt_on 管自定义工具的人在回路。

规则按声明顺序、先匹配先生效。更具体的规则放前面。默认是放行，所以最后通常要有一条总闸。人在回路必须带 checkpointer，否则中断后无法恢复。 

from deepagents import FilesystemPermission, create_deep_agent
from langgraph.checkpoint.memory import MemorySaver

checkpointer = MemorySaver()

agent = create_deep_agent(
    model="anthropic:claude-sonnet-4-6",
    system_prompt=SYSTEM_PROMPT,
    tools=[lookup_stock, notify_email],
    backend=backend,
    checkpointer=checkpointer,
    permissions=[
        FilesystemPermission(
            operations=["write"],
            paths=["/workspace/.env", "/workspace/secrets/**"],
            mode="deny",
        ),
        FilesystemPermission(
            operations=["write"],
            paths=["/workspace/outbox/**"],
            mode="interrupt",
        ),
        FilesystemPermission(
            operations=["read", "write"],
            paths=["/workspace/**"],
            mode="allow",
        ),
        FilesystemPermission(
            operations=["read", "write"],
            paths=["/**"],
            mode="deny",
        ),
    ],
    interrupt_on={
        "lookup_stock": False,
        "notify_email": {"allowed_decisions": ["approve", "reject"]},
    },
)

明晚只箍三件事

  1. 工作区以外的读写全部 deny；.env 与密钥目录单独拒绝。
  2. 最终件目录用 mode="interrupt"，写出去之前必须有人点头。
  3. 对客发送、删数据、改生产配置走 interrupt_on，只允许批准或拒绝，不给模型当场改参数的自由。

permissions 只管内置文件系统工具。自定义工具、MCP、以及沙箱里的 execute 不会自动遵守这些规则。危险动作必须同时出现在 interrupt_on 里。

后天：Skill + 独立检查

说明书负责「你是谁」；Skill 负责「这类活怎么做」。Skill 按 Agent Skills 规范放在目录里，入口是 SKILL.md。Deep Agents 启动时只读 name / description，真正用到才加载全文——这叫渐进披露，别把整本操作手册塞进 system_prompt。

独立检查是另一条原则：写稿的 Agent 不能给自己盖章。派一个只读子 Agent，对照验收清单看草稿，只输出通过 / 驳回和理由。 

from deepagents import FilesystemPermission, create_deep_agent
from deepagents.backends.filesystem import FilesystemBackend
from langgraph.checkpoint.memory import MemorySaver

backend = FilesystemBackend(root_dir="./ops-agent")

reviewer = {
    "name": "draft-auditor",
    "description": "只读检查 outbox 草稿是否可发，不改文件、不发送。",
    "system_prompt": (
        "你是独立检查员。只读 /workspace/outbox/。"
        "核对：SKU 来自工具结果、库存结论可追溯、话术未承诺无法发货。"
        "输出 PASS 或 REJECT，附三条以内理由。"
    ),
    "tools": [],
    "permissions": [
        FilesystemPermission(operations=["write"], paths=["/**"], mode="deny"),
        FilesystemPermission(operations=["read"], paths=["/workspace/outbox/**"], mode="allow"),
        FilesystemPermission(operations=["read"], paths=["/**"], mode="deny"),
    ],
}

agent = create_deep_agent(
    model="anthropic:claude-sonnet-4-6",
    system_prompt=SYSTEM_PROMPT,
    tools=[lookup_stock, notify_email],
    backend=backend,
    skills=["./skills/"],
    subagents=[reviewer],
    permissions=[
        FilesystemPermission(operations=["write"], paths=["/workspace/outbox/**"], mode="interrupt"),
        FilesystemPermission(operations=["read", "write"], paths=["/workspace/**"], mode="allow"),
        FilesystemPermission(operations=["read", "write"], paths=["/**"], mode="deny"),
    ],
    interrupt_on={"notify_email": {"allowed_decisions": ["approve", "reject"]}},
    checkpointer=MemorySaver(),
)

一个够用的 Skill 长什么样

skills/stock-reply/SKILL.md 只写黄金路径：何时查库存、草稿字段、何时必须停手、何时交给检查员。脚本、模板、字段表可以放在同目录，并在 Skill 正文里写清「什么时候读哪个文件」。 

---
name: stock-reply
description: 处理能否发货咨询。先查库存，再写 outbox 草稿，最后交给 draft-auditor。
---

# stock-reply

1. 用 lookup_stock 查 SKU；NOT_FOUND 或数量不足就停，并写明原因。
2. 草稿必须包含 sku、qty、结论、建议话术；结论必须能回溯到工具返回。
3. 写完后调用 draft-auditor。REJECT 则改草稿，不要直接 notify_email。
4. 只有 PASS 且人类批准后，才允许发送。

缰绳五层 → Deep Agents

把业务 Agent 做稳，可以看成五层缰绳。下面只映射到 Deep Agents 你这三晚会用到的接口，方便对照，不是框架全貌。

缰绳 你要它管什么 Deep Agents
指令 角色、边界、成功标准 system_prompt、memory / AGENTS.md
约束 能碰哪些文件、哪些工具必须停 permissions、interrupt_on
反馈 人能改判、中断后还能续跑 HITL + checkpointer；工具返回与拒绝原因
能力记忆 流程可复用，偏好能留下 skills、memory、backend / store 上的文件
编排 主路径、委派、验收分工 subagents、task、可选的 write_todos

今晚先指令，明晚先约束和反馈，后天补能力记忆与编排。五层都「听说过」不算做完；黄金路径上五层都有落点才算。
