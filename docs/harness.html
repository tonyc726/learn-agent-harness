橙皮书生长顺序

能力按这个顺序加，不要一上来上多 Agent。

  1. 空的 AGENTS.md：只写角色、边界、成功长什么样。
  2. 出错就加一条规则：每次真实失败，收成一条可执行约束，而不是再写一段口号。
  3. 接上反馈：可验收输出、日志、检查清单。模型看不到的错误，等于没发生。
  4. hooks / CI / sandbox：把「不能做」从自觉改成机械门闩。
  5. skills / MCP：领域流程可复用之后，再接外部工具。
  6. 多 Agent 放最后：一条路径还箍不住时，加子 Agent 只会放大含糊。

Track A 的三晚只对照 §01 / §04 / §10。Track B 才按上面的顺序把整条缰绳长完。不摘录橙皮书正文。

0–6 周课表

每周只交付一个能跑的增量。前三周可以继续用 Deep Agents；后三周才拆别人的文件。

周 缰绳动作 对照
0 写下空的 AGENTS.md：角色、边界、成功标准。不接新工具。 橙皮书生长第 1 步；Deep Agents Overview
1 每出现一次真实错误，加一条规则。说明书只增不改题。 出错就加规则
2 接上反馈：结构化输出、日志、检查清单。模型看不见的失败，当成没发生。 反馈层
3 hooks / CI / sandbox。把危险动作改成门闩，而不是提示词里的「请不要」。 Pi agent-loop.ts + agent-session.ts
4 skills / MCP。领域流程可复用之后，再接外部工具。 Codex turn.rs + orchestrator.rs + sandboxing
5 读 dsh 怎么把一切做成插件。先架构与 Cordis，再动手加工具。 architecture.md → cordis-primer → tutorial 01–07
6 补一个工具，再读默认循环。多 Agent 仍放最后——一条路径不稳就不拆成一群人。 adding-a-tool.md → agent.ts
