学的是 harness

从零造一个循环

模型只会说话。下面五个文件是最小 harness。

往下读，右边／底下的代码会跟着长出来。五个文件 llm.ts agent.ts tools.ts tui.ts cli.ts。

读到哪一份，工具箱就亮哪一份。想停在某一份，点工具箱上的锁。

llm.ts

先能问到模型

没有这一层，循环对着空气说话。模型在网线那头。请求怎么拼、SSE 怎么拆、半截工具参数怎么粘，都停在这里。上层只收四种事件，不要去碰 HTTP。

对外交出 stream：Context 进，StreamEvent 出。事件只有 text_delta、tool_call、done、error。只接 OpenAI 兼容口。

Context 是喂给模型的东西：一段 system，加上 messages。纯数据，上层不用管供应商字段。

agent.ts

让模型用得上工具

一次 stream 结束就散了，工具结果回不去。runAgent 拉 stream。若是 tool_call，执行、把结果追加进 Context、再问。直到 done。

往外吐的是 AgentEvent，不是 StreamEvent。屏幕只认这一套：文本、工具、这一轮完了。

tools.ts

四个纯函数干活

循环只会调度。read_file write_file edit run_bash。它们不认识 Context，也不认识循环。

教学剂，没有批准。生产里要有人点头；这里故意卸掉，只看数据怎么流。

tui.ts

屏幕只认 AgentEvent

终端只听 AgentEvent。HTTP、SSE、供应商字段，一概不进这一层。

attachTui 读一行输入，按事件往终端写。它不认 HTTP。换成网页，agent 不用改。

cli.ts

胶水，加上一本账

cli 读配置，把人那一行塞进 Context，把 AgentEvent 转给屏幕，每轮把消息追加进 session.jsonl。

cli 认识所有人。tools 不认识 agent。

数据流

用户 → tui → cli → agent → llm

有 tool_call 就走 tools，把结果写回，再问。每轮结束，cli 把消息追加进 session.jsonl。依赖单向。

完整版对照。官方循环 earendil-works/pi packages/agent/src/agent-loop.ts。
