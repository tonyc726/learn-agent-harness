    口头「开了」不能写库

    练习：口头说「开了」，什么也没写进库。

    先挨打

    你对模型说「把门禁开了」。它说「好了」。规则还是停用。确认坞是空的。

    你

    把门禁开了

    模型

    好了。已经开了。

    确认坞

    空。无人批准。

    规则

    notify-on-red · 停用

    先回忆再讲

    模型回了「好了」。规则启用了吗？

    看确认坞。空的。

    模型能自己调用 commit 吗？

    工具只有查询和起草。没有提交。

    先做再给答案

    勾出刚才看见的两件实事。不要勾「它说好了就算」。

    过关看证物

    聊天里的「好了」不是门闩。启用必须经过确认坞。模型看不见 commit。

    第 1 关

    先写说明书

    练习任务：说明书写清只开门禁，不许发版。

    先挨打

    你写「帮我处理一下 CI」。模型启用了通知，也点了发版。合同没写「只通知，不发版」。

    你

    帮我处理一下 CI

    模型

    通知开了。发版也帮你点了。

    流水线

    deploy · 已触发

    先回忆再讲

    这份合同要让 Agent 做什么？

    一门差事。发版不在门里。

    合同必须钉死的是哪五句？

    合同管边界，不管采样参数。

    先做再给答案

    先写五句，或点「填入范例」。必须写明：只启用通知规则，不要自动发版。

    过关看证物

    一份够用的合同可以长这样。你的五句已经进坞。不必抄。

    你是仓库里的开发助手，只服务这一条：启用「CI 红了先通知，不要自动发版」。
成功：规则先以停用草稿落盘；启用必须经过确认坞；CI 红了只发群通知。
工具：list_pipelines、draft_rule、read_receipt。没有 deploy，没有 commit。
工作区：只读写约定目录。草稿与回执分开。
停手：缺权限、有人要发版、或偏离通知规则时，写明原因并等待。

    令牌进了聊天。问题出在哪？

    模型只能看见投影给它的字段。

    安全投影该留下什么？

    能辨认、能对版本、能看状态就够。

    第 3 关

    先停用，再申请启用

    练习任务：先停用「红了先通知」，再申请启用。

    先挨打

    模型想一笔写成「已启用」。进程在中途崩了。没有回执。没人说得清通知开没开。

    模型

    我直接写成启用，省一步。

    进程

    崩溃。领域写了一半。回执缺失。

    规则

    未知。可能开，可能没开。

    先回忆再讲

    为什么先写成停用草稿？

    先有 rule id 和 revision，启用才有东西可批。

    一回合能写几次？

    一次写，一张回执。叠写就对不上。

    先做再给答案

    把规则写成停用。本回合只许写一次。

    过关看证物

    回执先承认「写过、仍停用」。启用是下一关的事。

    rule_id: rule-ci-notify
revision: r1
enabled: false
writes_this_turn: 1

    先挨打

    开了

    模型

    好了。

    确认坞

    待批准。无人键入。

    规则

    r1 · 停用

    先回忆再讲

    谁能触发 commit？

    commit 不在模型的工具清单里。

    确认坞必须先展示什么？

    先看见要开的是什么，再键入。

    先做再给答案

    旧确认必须作废

    练习：有人改过规则，旧确认作废。批准的必须是你看见的那一版。

    先挨打

    你离开的时候，同事把通知对象改成全员，分支改成 main。坞里还躺着你那张旧批准。

    草稿 r2

    旧卡 r1

    notify=团队群 · branch=release · token 仍在

    先回忆再讲

    同事改了通知对象或分支。旧批准还能用吗？

    批的是 r1。现在是 r2。

    发现不匹配时该做什么？

    启用同事改过的配置，算失败。

    先做再给答案

    你批准过的

    revision r1
    notify 团队群
    branch release
    token tok-r1

    现在的草稿

    revision r2
    notify 全员
    branch main
    token 应对 tok-r2

    对话停了，CI 还在

    练习：对话停了，CI 还在；断了去对账，别瞎重试。

    先挨打

    你点了「停止生成」。聊天停了。CI 还在跑。同时，领域写成功、回执没落，状态变成 unknown。有人当失败，又写了一条。

    你

    停止生成

    聊天

    回合停了。

    CI

    仍在跑。

    回执

    intent int-7 · unknown

    先回忆再讲

    点了「停止生成」，正在跑的 CI 会怎样？

    停止生成只停这一轮对话。

    写库成功、回执没落，该怎么办？

    同一条 intent 收敛。不要新开一条，也不要两阶段提交。

    先做再给答案

    unknown · intent int-7 · 领域：规则已写 · 回执：缺失

    过关看证物

    停止生成不是取消 CI。unknown 按同一条 intent 收敛。结果可知、重试安全一起亮。

    stop_generate: chat_turn_only
cancel_ci: separate_command
intent_id: int-7
unknown: converged
twopc: false
